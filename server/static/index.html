「暂停周期」= 建一条 kind=pause 任务（POST /api/v1/tasks，带 duration_s）→ 板端 ≤3 s 轮询领取 → 停止喂 1 s 周期上传窗口 （采样、SD/CSV 落盘、屏幕刷新照旧，手动采集仍可用）→ 板端 POST /api/v1/tasks/{id}/applied 确认已生效，任务完成。
本卡片的状态来自 GET /api/v1/control：服务端 device_control 表是「是否真的停止上报」的真相源，不靠「周期批次数为 0」反推。 暂停到期自动恢复（板端按自己的定时器自愈，服务端把到期的记录惰性归零）， 所以忘记点「恢复周期」也不会永久静默；点「恢复周期」= 建一条 kind=resume 任务提前恢复。方向相反的两条控制任务不会同时排队（新的一条会把旧的置 failed: superseded by newer control task）。

板端长按 Button A（2 s）开始推流：live_stream_task 循环「拍一帧 640×480 JPEG（esp_video/DVP，原始字节直传）→ POST /api/v1/live?device_id=…&ts_ms=…&w=…&h=…」， 约 2-4 fps；再长按一次停止（LCD 状态栏会显示 Live:ON/OFF）。
服务端只在内存里保留每台设备的最新一帧（不落盘、不进 photos 表、不建任务）， 本卡片以独立 250 ms 节拍按 GET /api/v1/live 的 seq 轮询 GET /api/v1/live/frame 刷新 <img>，即得到实时画面。直播是连续流：丢一帧下一帧立刻补上， 不做逐帧 ACK；超过 5 s 没有新帧即视为「未推流」（板端按停止 / 断网 / 掉电），画面停在最后一帧而不是报错。
直播与「拍一张照片」共用相机，板端用互斥锁串行化（单帧拍照最多等多一帧的时间）； 不占用 IMU 采样器、不暂停周期上报。
